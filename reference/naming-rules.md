# L4D2 MOD 分类命名 · 工作流规范 v1.0（已定稿）

> 状态：**所有规则已确认**，可据此执行改名，也可直接作为 skill 的规则源。
> 定稿依据：127 个真实 mod × 22,304 条真实 VPK 路径的实测推演。

---

## 1. 总原则

1. **原标题永不改动**（除 Windows 非法字符全角化）。规则只决定**分类前缀**与**替换对象**两段。
2. **分类前缀 = mod 的身份**，不是它顺带改了哪些文件。
   > 反例：778 MB 地图包 `myl4d2addons_glubtastic5` 顺带带了坦克模型，不能被叫「特感」。
3. **置信度分层**：规则只在**高置信**时改写前缀；低置信时**保留人工前缀**并列入待复核，绝不静默猜。

## 3. 判定顺序（自上而下，命中即止）

### S1 · 地图类 【高置信】
- 判据：路径含 `maps/*.bsp` 或 `maps/*.nav`
- → `地图-`
- 实测覆盖 13 个（含 `脚本-The Ultimate Mod Testing and Reviewing Area`，它确实是一张测试地图）
- 已知盲点：`地图-Secret …（fix）`（975 条路径，无 bsp / 无 nav）→ 落 S5 保留

### 专项（2）：`手电筒-` / `管理员插件-`（2026-10-03 新增）

形态**同资源类型**：省略中段（`手电筒-<原标题>`）。

| 前缀 | 判定 | 占比门槛 |
|---|---|---|
| `手电筒-` | 只认**手电筒本体**：`^materials/effects/flashlight` 与 `^models/.*flashlight`。**故意不认** `materials/particle/(beam_)?flashlight*` / `flashlight_glow*` —— 那是粒子包/菜单的共享光束与光晕资源，实测有 3 个菜单/粒子 mod 顺带带了它们 | ≥25% |
| `管理员插件-` | VScript 管理入口（`^scripts/vscripts/[^/]*admin`）+ SourceMod / MetaMod（`^(addons/)?(sourcemod|metamod)/`、`^cfg/sourcemod/`、`\.smx$`）。**不认 `sm_*`**（那是通用 VScript 工具库，如 Turret Mod 的 `sm_utilities.nut`） | ≥25% |

两者都放在 **S4**（物件域判不出来之后），且优先于模型/素材判定。

> **为什么要占比门槛**：实测 `材质-ESC菜单 Kokomi自用版` 4 条路径里有 2 条手电筒贴图（50%），
> 但它其实是菜单 mod —— 光靠「命中即算」会把它误判成手电筒（附带覆盖陷阱）。
> 真实成员占比：手电筒 100%、管理员插件 79%。

### S2 · 物件域 【高置信】
三个条件同时满足：
1. 有**物件标签**命中（`label_map.json` 里映射到 10 个物件域之一的标签）
2. 该 mod **含模型文件**（`.mdl` / `.vvd` / `.vtx` / `.phy` / `.ani`）
3. **域相关路径占比 ≥ 5%**

域相关路径 = 该域物件标签命中路径 ＋ 该域**邻接标签**命中路径
邻接标签映射：
| 邻接标签 | 归属域 |
|---|---|
| `材质·生还者贴图` | 生还者 |
| `材质·感染者贴图` | 特殊感染者 |
| `动画·感染者骨骼` | 特殊感染者 |
| `音效·生还者技能音效` | 生还者 |
| `语音·<角色>` | 生还者 |
| `音效·<武器名>` | 用标签尾巴去匹配各域行的中文名（如 `音效·AK-47` → 主武器） |

> ⚠️ **邻接映射不能省**。实测 `角色-Nick-COD：MWII Ghost` 的物件标签只命中 4 条路径，
> 其余 305 条全被归进 `材质·生还者贴图`；没有邻接映射它会被判成 `材质-`。

多域命中时取**域优先级**最高者：
`生还者 → 特感 → 普感 → 主武器 → 副武器 → 近战 → 投掷物 → 消耗品 → 场景道具 → 场景`

### S3 · 物件域（贴图/音效类物件）【中置信】
- 判据：有物件标签、占比 ≥ 5%，但**不含模型文件**
- → 仍用物件域前缀，**列入待复核**
- 例：`材质-全部梯子-HD Luminous ladder`（只出 `materials/`）→ `场景-梯子-…` + 待复核

### S4 · 资源类型 【高置信】
- 判据：S2/S3 不成立 → 取路径数最多的**资源类型标签**映射前缀
- `未归类` 不参与排序，直接跳过

### S5 · 保留原前缀 【低置信】
任一成立即落此：
- S1–S4 都不成立
- 域相关占比 < 5%
- **`未归类` 占比 > 50%**（标签体系没覆盖到，判定不可靠）
→ **原名不动**，写入待复核

> S5 的实测受益者：`效果-The Particles Manifest`（未归类 79%）保住了 `效果-`，
> `界面-V社启动动画`、`界面-大厅背景`（未归类 100%）保住了 `界面-`。

### ❌ 已被否决的做法：比例阈值当主判据
占比从 0.4% 到 100% **连续分布无断点**。曾试过「S2 门槛 25%」，结果 15 个毫无疑问的替换件
（Coach/Ellis/Louis/Rochelle/Zoey/Francis/Hunter/Spitter/Witch/UZI/MP5/SG552/M60/撬棍/砍刀）
全被误标为待复核；降到 5% 后**前缀分布完全不变、待复核从 20 条降到 4 条**。
→ 真正的判据是「**该域有没有模型文件**」，占比只作为噪声下限。

## 4. 横切行（不参与中段取值）

一个 mod 常同时命中「角色级行」和「横切行」。取中段时**必须先排除横切行**。

> 反例：`角色-Boomer-Snorlax (Boomer)` 命中 `爆炸残肢`(8 条) 比 `呕吐者`(4 条) 多，
> 「取占比最高那行」会命名成 `特感-爆炸残肢-Snorlax`。**正确是 `特感-Boomer-Snorlax`。**

| 表 | 横切行 | 无模型证据时默认前缀 |
|---|---|---|
| 生还者 | 生还者骨架动画 | `生还者-` |
| 生还者 | 生还者手势 | `生还者-` |
| 生还者 | 生还者通用音效 | `音效-` |
| 生还者 | 生还者语音 | `音效-` |
| 生还者 | HUD 头像 | `界面-` |
| 特感 | L4D1 版感染者模型 | `特感-` |
| 特感 | 感染者第一人称爪（第三人称视角模式） | `特感-` |
| 特感 | 感染者手臂 | `特感-` |
| 特感 | 爆炸残肢 | `特感-` |
| 普感 | 女性感染者残肢模型 | `普感-` |
| 普感 | 普通感染者残肢模型 | `普感-` |
| 普感 | 血块与碎尸 | `普感-` |

**只有当 mod「只」命中横切行时**，才把横切行当中段。

# v1.1 补充（2026-10-03 实执行后）

前面 v1.0 的规则**已全量执行**（74 条改名 + 1 条例外改名），下面是执行中暴露、必须写进 skill 的四件事。

## A · 执行流水线（顺序不能颠倒）

```
刷新表格.bat nopause          # 重扫 addons → addons_scan.json / label_map.json / xlsx
  ↓
rv_dump_paths.mjs            # 自写解析器解全部 VPK 完整路径 → rv_paths.json
  ↓
plan_v4.py                   # S1–S5 推演 → rename_plan.md（含规则例外）
  ↓
mk_rename_json.py            # 出批次 → rename_batch.json
  ↓
rename_batch.ps1 -Batch <json>            # 干跑
rename_batch.ps1 -Batch <json> -Apply     # 执行（vpk+jpg+url 三件同步）
```

⚠️ **`rv_paths.json` 是按文件名索引的，改名后必须重跑 `rv_dump_paths.mjs`**。
实测踩过：改名后直接重跑推演，`地图-myl4d2addons_glubtastic5` 查不到自己的路径列表 →
检测不到 `maps/*.bsp` 与模型文件 → 被误判成 `特感-Tank-…`。

## B · 幂等性（skill 的硬要求）

**在已按规范整理好的库上重跑，必须提出 0 条改动。** 实测已达成。

`newname()` 的幂等保护：
```python
want = '%s-%s' % (pre, tgt) if tgt else pre
if stem == want or stem.startswith(want + '-'):
    return stem          # 已经符合目标「前缀-替换对象」，原样保留
```
⚠️ **不能靠「按短横切分」去剥旧替换对象**——新替换对象自己就可能带短横（`AK-47 突击步枪`、`M-16 突击步枪`），
切分会把名字切坏成 `主武器-AK-47 突击步枪-47 突击步枪-[AK47] …`。
正确写法是「前缀匹配」：若当前名已以 `新前缀-新替换对象-` 开头就原样返回。

## C · 规则例外表（`_work\name_exempt.json`）

用户拍板的取舍必须落到这里，否则重跑规则会把名字推回去。`plan_v4.py` 已读该文件并按 `name` 固定。

| mod | 规则会说 | 用户裁定 | 理由 |
|---|---|---|---|
| `材质-BLOODIER GUTS AND GIBS!` | `普感-血块与碎尸-BLOODIER GUTS AND GIBS!` | **`材质-`（保持）** | 纯贴图类：12 条路径全是 `materials/models/infected/gibs\|common/` 下的 vmt，无任何模型文件。叫「普感」名不副实 |
| `特感-骨架动画-xdReanimsBase (L4D2) Anim Mods base` | `生还者-骨架动画-…` | **`特感-骨架动画-…`** | 它同时带 `models/infected/anim_*.mdl` 与 `models/survivors/anim_*.mdl`；作者命名与用途都在特感侧 |

两条例外界定了 S2/S3 的边界：
- **S3 的边界**：「只改贴图的物件 mod」应归物件域，**但当那个物件域本身是一个「横切行」时**（血块与碎尸），直接用资源类型前缀更准确。
- **S2 的边界**：跨物件域、且两侧都是横切行时，**域优先级不足以决定，必须人工**。

## D · 执行后的连带更新（漏一项就会不自洽）

1. `mod白名单.txt` —— 条目换新名；撤销的豁免要**删条目**（不是加注释）；清理 mod 已不在库里的过期条目
   - ⚠️ 它的解析规则是「行首就是 `<前缀>-` 的行才算条目」→ **写中文说明时别让续行以 `<前缀>-` 开头**（本次误收过一行）
2. `set_exempt.json` —— 多件套成员换新名（否则扫描器认不出多件套，会报假冲突）
3. `mod备份\backup_manifest.md` —— 冲突移走的补行 + 记「kept instead」列旧名对照
4. `scan_targets.ps1` 的 `$cats` —— 跟着前缀表更新（现 22 项，含旧名兼容）
5. `刷新表格.bat nopause` —— 让 xlsx 跟上新文件名

## E · `scan_targets.ps1` 覆盖面大幅下降（重要）

改名后 **74 条里有 54 条落到资源类型前缀**（`材质-` `脚本-` `界面-` …），**中段为空**，
按「前缀 + 第 2 段」分组的文件名扫描器**判不了它们**。

→ **冲突判定应以表格标签链路为准**：`addons_scan.json` + `label_map.json` + `verify_overlaps.py`。
`scan_targets.ps1` 降级为辅助（它现在只能覆盖物件域前缀的那些，外加白名单/多件套校验）。

## F · `效果-` 前缀已废弃

`效果-` 的 2 个 mod 分别归入 `特效-The Particles Manifest` 与 `材质-Infinite Warfare Effects Support`。
**19 个前缀里不再有 `效果-`。**

## H · 标题自带 `(Part N)` 的三件套：按【成员】登记，别去凑前缀

M200 三件套能用 `is_set()`（**按名字前缀**）自动认出来，因为附加件命名是 `主体名 + -附加名`。
Cold Front **不适用**——三个成员各自标题自带 `(Part N)`，为凑前缀而改名会违反「原标题永不改动」。
所以 `verify_overlaps.py` 的 `is_set()` 与 `scan_targets.ps1` 的前缀分组**都认不出它**，
只能在 `set_exempt.json` 里**按成员名单**登记 —— 正是硬约束 7 说的「豁免按成员声明，不是按组键」。

好在三件文件名都以 `地图-` 开头 → 命中 `incidental`（算「地图/战役包附带」），重叠检查不会误报。
但这只是**当下**成立；一旦判定逻辑变化，登记就是唯一的保护。
